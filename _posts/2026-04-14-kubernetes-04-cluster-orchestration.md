쿠버네티스를 이해하려면 오케스트레이션이라는 말을 먼저 잡아야 한다. 오케스트레이션은 여러 서버와 여러 컨테이너를 하나의 시스템처럼 조율하는 일이다. 쿠버네티스는 이 조율을 자동화한다.

## 클러스터는 서버 묶음이다

쿠버네티스에서 클러스터는 여러 서버를 하나로 묶어 관리하는 단위다. 서버 한 대를 Node라고 부르고, 여러 Node가 모이면 클러스터가 된다. 애플리케이션은 이 클러스터 위에서 컨테이너 단위로 실행된다.

운영자는 특정 서버에 직접 컨테이너를 띄우는 대신, 쿠버네티스에게 원하는 상태를 선언한다. 예를 들어 `nginx를 3개 유지해줘`라고 선언하면, 쿠버네티스가 노드 상태를 보고 적절한 위치에 배치한다.

## Desired State와 Current State

쿠버네티스의 핵심은 원하는 상태와 현재 상태를 비교하는 것이다. 원하는 상태는 사용자가 선언한 목표다. 현재 상태는 실제 클러스터가 가지고 있는 상태다.

예를 들어 원하는 상태가 Pod 3개인데 현재 상태가 2개라면, 쿠버네티스는 Pod 하나를 더 만든다. 반대로 현재 상태가 4개라면 하나를 줄인다. 이처럼 현재 상태를 원하는 상태에 맞추는 반복 작업이 쿠버네티스의 기본 동작이다.

## Scheduling

새로운 Pod를 만들 때 어느 Node에 배치할지 정하는 작업을 Scheduling이라고 한다. 스케줄러는 각 Node의 리소스 상태와 제약 조건을 보고 적절한 위치를 선택한다.

이 과정 덕분에 운영자는 모든 서버의 여유 자원을 직접 확인하지 않아도 된다. 쿠버네티스가 클러스터 전체를 보고 배치 결정을 내린다.

## Rollout과 Rollback

쿠버네티스는 버전 변경도 관리한다. 새 버전을 배포할 때 한 번에 모두 바꾸는 것이 아니라, 점진적으로 교체할 수 있다. 문제가 생기면 이전 버전으로 되돌리는 Rollback도 가능하다.

이 기능은 Deployment를 사용할 때 특히 중요하다. Deployment는 내부적으로 ReplicaSet을 관리하면서 애플리케이션 버전과 Pod 개수를 조정한다.

## 정리

클러스터 오케스트레이션은 서버 묶음 위에서 컨테이너를 자동으로 배치하고, 상태를 유지하고, 버전을 관리하고, 네트워크 연결을 안정화하는 일이다. 쿠버네티스는 이 모든 작업을 선언형 방식으로 처리한다.
